# 2026-07-27 Devlog

## 今日摘要

今天將專案由單一胸痛問診頁面擴展為支援胸痛、頭痛與腹痛的 AI 預問診系統，
完成 Vue 3 前端、JSON 動態問卷、FHIR 病歷預填，以及依主訴路由的 RAG v2
檢索流程。另補齊測試、環境設定與新版架構文件，並整合遠端 `main` 歷史。

## 動態問卷與後端

- 將主訴、基本資料、一般病史、胸痛、頭痛及腹痛問卷拆分為獨立 JSON，
  讓題目內容可在不修改主程式的情況下維護。
- 新增問卷 lazy loader、快取與 schema 驗證，支援文字、選擇、日期、時間長度
  及條件式題目。
- 依自由主訴選擇胸痛、頭痛或腹痛流程；明確關鍵字優先，無法確定時再使用
  LLM 分流。
- 抽離 LLM client，統一 Groq／Gemini provider 與模型選擇，並處理 Gemini
  thinking budget 及空回應重試。
- 更新 FastAPI 問診流程、語音辨識修正、結構化回答、報告產生與醫師端
  六段式病歷分析。

## FHIR 整合

- 建立 Vue 測試模式的 HAPI FHIR 直連流程，可使用台灣身分證 identifier
  查詢病人並載入 `Patient/{id}/$everything`。
- 將 Patient 基本資料、Condition、Procedure、MedicationStatement、
  MedicationRequest、AllergyIntolerance 與 QuestionnaireResponse
  映射為問診預填欄位。
- 已由 FHIR 取得的基本資料與病史會自動略過，避免重複詢問。
- 身分證字號只用於 FHIR 查詢，不會送入 `/chat`、RAG 或外部模型。
- 排除本次 encounter diagnosis，避免將當次就診診斷誤判為既往病史。
- 新增合成胸痛 FHIR Bundle，供本機 HAPI Server 測試。

## RAG v2

- 新增醫療爬蟲語料清理與 chunk 切分流程。
- 建立多標籤分類器，將內容分至胸痛、頭痛、腹痛、共通、安全與 archive，
  並輸出統計及人工審查清單。
- 建立五個 versioned Chroma collections，保留舊版 `medical_kb` 以支援回退。
- 依主訴選擇內容庫並固定加入 safety collection；不確定查詢可追加 common
  或第二個症狀庫。
- 使用 Reciprocal Rank Fusion 合併、去重檢索結果，並限制單篇文章佔用的
  chunk 數量。
- 新增固定黃金案例與 legacy／v2 比較工具。
- 加入實驗性的 Gemini 中英查詢正規化：送出前遮蔽直接識別資訊，支援
  dual-query 與 english-only 模式，失敗時退回原多語 embedding 查詢。

## Vue 前端

- 建立 Vue 3、Vite 與 hash router 專案架構，提供病患端 `/#/` 與醫師端
  `/#/doctor`。
- 將頁面拆分為 Header、聊天訊息、輸入提示、人體疼痛圖、排隊號碼、
  病歷卡、結構化報告及來源標籤等元件。
- 病患端支援文字、語音、單選／複選、日期、時間長度、自由補充及正背面
  人體疼痛位置標記。
- 保留 D-ID Avatar 設定與語音互動，未連接 Avatar 時仍可完成純文字問診。
- 醫師端可依問診編號載入病人資料、疼痛位置與 AI 報告，並針對補充資訊
  產生結構化病歷分析。
- 保留根目錄舊版 HTML，供重構期間相容與比對。
