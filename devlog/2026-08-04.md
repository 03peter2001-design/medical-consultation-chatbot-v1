# 2026-08-04 Devlog

## 今日摘要

今天將醫師端臨床規則中心擴充為可治理疾病票數、Safety 觸發與
ClinicalFact 標籤的完整工作流，並為所有 API 建立版本化 `/v1` 契約、
OpenAPI 規格及前端型別同步機制。同步重整醫師速覽摘要與 EMR 顯示，讓
生成式模型只整理既有病史，可能疾病與理由則完全由固定疾病表及病人原始
支持線索組成。

## 疾病規則與 Safety 治理

- 將規則中心拆成疾病票數、ClinicalFact 標籤及組合／原文 Safety 規則三個
  獨立元件，降低單一頁面的複雜度並保留既有管理權杖流程。
- 醫師可依胸痛、頭痛或腹痛疾病表編輯既有疾病線索，新增或移除白名單 fact，
  設定存在／不存在、支持／反對方向，以及 1 至 10 的整數權重；疾病本身不可
  新增或刪除。
- 為每個疾病 profile 加入 reviewer、reviewed_at 與穩定的
  `safety_rule_codes`。不能漏診疾病必須綁定至少一組適用於該 route 的 Safety
  規則，普通支持票不會自行升級為 urgent。
- 新增疾病表發布 API，包含管理權杖、指定確認文字、審查醫師、變更理由、版本
  衝突、完整集合驗證、逐項差異稽核、原子寫入及失敗回復。
- 建立可編輯的完整 ClinicalFact catalog。穩定 code 不可更名或刪除，但可校訂
  說明並切換直接 Safety 標籤；以 present 命中直接 Safety fact 時會立即觸發
  urgent。
- 新增 ClinicalFact 獨立發布及稽核流程，並補齊 onset 定義、fact 說明解析、
  route 適用性與疾病 profile schema 驗證。
- 擴充三套疾病表的線索、來源及 Safety 綁定資料，讓規則中心可呈現並治理完整
  疾病方向；受影響疾病發布後會標記為 reviewed 並產生新 profile version。

## 版本化 API 與契約

- 正式 API 統一使用 `/v1` 前綴；既有未版本化路徑暫時保留為不列入 OpenAPI
  的相容別名，避免現有整合立即中斷。
- 為系統、病患與醫師端路由補上具名 response model、錯誤 envelope、標籤、
  摘要及狀態碼說明，讓成功與錯誤契約可以由 FastAPI 統一輸出。
- 新增 `backend/scripts/export_openapi.py`，可產生或檢查版本控制中的
  `docs/openapi.json`，並以契約測試確認只有 `/v1` 路徑公開、operation ID 唯一、
  成功回應皆具型別，代表性執行期資料也能通過 response model。
- 前端 API client 全面切換至 `/v1`，新增 `openapi-typescript` 指令與產生的
  `frontend/src/generated/api.d.ts`，可在 CI 或提交前檢查規格與型別是否過期。
- SMART Compose、啟動腳本與相關文件同步改用 `/api/v1/health`。

## 醫師速覽摘要與 EMR

- 將背景報告改為醫師快速閱讀的一段式病史摘要；Gemini 只壓縮已知病史，不得
  自行提出疾病、診斷、檢查或治療建議。
- 後端從 Safety 觸發疾病及固定疾病表票數中選取最多三個具支持線索的疾病，附上
  病人原始 evidence，再與病史摘要組成約 300 字的醫師速覽，並明示不是正式診斷。
- 醫師病例卡新增獨立的「病歷摘要 EMR」區塊；結構化報告在病例載入時會隱藏
  已經置頂呈現的 EMR 段落，避免同一內容重複顯示。
- 新增結構化病歷切分工具及前端測試，並調整病例卡、報告標題與行動版樣式。
