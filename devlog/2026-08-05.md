# 2026-08-05 Devlog

## 今日摘要

今天將醫師規則治理與病患問診 route 拆成較小、可獨立測試的模組，並為
確定性疾病投票加入動態候選漏斗，使下一題可依目前支持票、區辨力、確認力與
反證力排序。病例儲存則改以「看診日期＋掛號編號」形成穩定識別，讓每日重用的
urgent／routine 號碼仍可正確查詢、載入、更新與刪除歷史病例。SMART sandbox
同步改用 Compose 內的 HAPI hostname，啟動時會補入兩筆合成病人資料。

## 問診與規則治理模組化

- 將病患問診中的 route 判斷、FHIR 預填、跨症狀預填、段落轉場、urgent 疾病方向
  與 AMIE session 初始化抽至 `patient_interview.py`，縮小 patient route 的責任範圍。
- 將規則中心後端拆成 read model、validation、publisher、assistant 與 common
  support 模組，保留既有 facade 與測試 patch seam，讓 API 呼叫端不需改寫。
- 將疾病治理與 Safety 治理的大型 Vue 元件拆成選擇器、編輯器、發布面板及
  composable；補上 payload 正規化、變更偵測、驗證與 filter reset 單元測試。

## 確定性疾病選題漏斗

- 疾病投票會依目前支持票建立動態候選群；尚無支持票時保留全部疾病廣泛區辨，
  有支持票時只追蹤距第一名指定票數內的候選，並限制候選數量。
- 選題仍維持 Safety、必要欄位與一般問題的固定層級；同層題目再依候選疾病間的
  區辨分、單一領先疾病的確認分與反證分進行確定性排序，不交由 LLM 決定。
- 三套路由問卷 policy 升級至 schema version 2，加入 `frontier_vote_margin=2` 與
  `frontier_max_candidates=5`，並在規則中心呈現設定值。
- 每輪稽核新增漏斗階段、選題層級、候選疾病、目標 ClinicalFact 及分數；醫師端
  Clinical Evidence 與 debug trace 可閱讀這些資訊，但病患 debug payload 不暴露
  疾病名稱、票數或完整候選排名。

## 跨日期病例識別與 SQLite 遷移

- SQLite schema 升級至 version 6，以 `YYYY-MM-DD:掛號編號` 作為永久
  `consultation_id`；urgent 每日從 `000` 起，routine 每日從 `10000` 起，並以
  `Asia/Taipei` 作為預設看診日期時區。
- 新增每日掛號 sequence、WAL lock contention retry、嚴格 ASCII ID／日期解析，
  以及從舊 schema 回填日期與穩定 composite ID 的交易式 migration。
- 所有背景摘要、結構化病歷、狀態更新與刪除改以 `consultation_id` 定位；只輸入
  掛號編號時可相容查詢，若跨日期重複則回傳 409 並要求指定日期。
- 醫師端病例卡、載入、刪除與 active state 改用 composite ID，畫面同時顯示看診
  日期與掛號編號；前端 API error 會將跨日期衝突轉成可操作提示。
- OpenAPI 契約與前端產生型別同步新增 `consultation_id`、`consultation_date`、
  `registration_number` 與 `created_at`，並補上 migration、並行初始化、跨日同號、
  lookup／delete 與契約回歸測試。
