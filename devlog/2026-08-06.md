# 2026-08-06 Devlog

## 今日摘要

今天完成 UCC 醫師端與外部病患端的身分邊界強化，將原本共用的 Vue 前端拆成獨立的 doctor／patient 應用，並補齊 Windows IIS、Ubuntu Nginx、Docker Compose 與 SQLite 備份還原的整合部署藍圖。後端新增 RS256 JWT 驗證、一次性病患邀請、HttpOnly session、機構隔離與安全稽核，避免由瀏覽器輸入的識別資料直接成為授權依據。

## 後端安全與授權

- 新增 UCC RS256 JWT 驗證與 scope 檢查，醫師 session 改以已驗證的機構、醫師與瀏覽器 session 組成隔離 key，並加鎖保護共享狀態。
- 新增病患邀請 API；邀請 token 僅供一次交換、只儲存雜湊，可撤銷舊邀請，交換後改用 Secure／HttpOnly cookie 維持病患 session。
- 病例查詢與變更綁定機構及授權 encounter，病患問診、語音轉錄與醫師管理端點加入對應的身分依賴。
- SQLite repository 新增 invitation、patient session、consultation access 與 security audit 資料結構及操作，保留交易與連線生命週期控制。
- 新增結構化安全稽核與安全日誌，避免 token、病歷內容或例外細節直接落入一般 application log。
- CORS 改為明確 allowlist；正式環境可停用未版本化 API alias，並在 `.env.example` 補上 JWT、cookie、公開病患網址與 CORS 設定說明。

## 醫師／病患雙前端

- 建立 npm workspace `frontend-v2`，分成 doctor app、patient app 與 shared clinical component library。
- 醫師端部署於 `/ai-consult/`，透過 UCC bootstrap 取得短效 access token 並只保存在記憶體；路由只暴露醫師工作台與規則中心。
- 病患端從 URL fragment 讀取邀請 token，經使用者確認後交換 HttpOnly session，隨即清除 fragment；不載入醫師 router 或醫師 API client。
- 將共用問診、FHIR、術語、結構化病歷、body map、規則治理與 clinical evidence 元件搬入 shared package，讓兩個 app 共用呈現但維持權限與 bundle 隔離。
- 新增 bootstrap、邀請 token、route isolation 與 production bundle source graph 測試。

## 整合部署

- 新增 Ubuntu Docker Compose 藍圖：Nginx 作為唯一入口，FastAPI 不發布 host port，病患與 UCC 流量分 listener、來源網段與路由限制。
- 新增 IIS `/ai-api` reverse proxy 規則、醫師靜態站 CSP，以及 PowerShell 醫師前端 build／安裝腳本。
- 新增 Ubuntu deploy、SQLite online backup 與需明確確認的 restore 腳本；部署文件涵蓋 TLS、憑證、firewall、單 worker、WAL、金鑰權限與驗收步驟。
- 新增靜態設定驗證腳本，檢查 placeholder、對外 port、worker 數、secret 權限設定與 Nginx 安全邊界。
- 將 `.deploy-staging/`、`frontend-v2/node_modules/` 與雙 app build 產物加入忽略，避免約 835 MB 的 eHIS 發佈暫存檔誤入版控。
