### 問卷內容與臨床治理

- 發現 49 份 `source_structured_provisional` 問卷雖仍標記待臨床簽核，卻可被 runtime
  自動發現並直接送入病人流程。現在只啟用既有 chest、headache、abdomen 三類；
  其餘保留為可驗證的候選內容，缺少核准時 fail closed。
- promotion 必須提供 clinical signoff manifest，包含 reviewer 身分與角色、審查日期、
  整體來源及 route catalog SHA-256、逐路由來源 hash／核准，以及所有 critical／warning
  note 的 resolution 與 rationale。核准產物保留 review notes、RAG sources 與 provenance。
- 撤回 headache／abdomen 三個尚未簽核的新選項。Syncope／出血等 disposition 對應及
  candidate route mapping 仍維持未核准狀態，沒有以工程決定取代臨床政策。
- frontend exporter 預設只處理 development frontend；`--frontend-v2` 才會觸及正式
  部署版，並新增 `--check`、drift detection 與原子寫入。

### AMIE 多主訴問診

- 修正 live `_clinical_facts` 與 legacy semantic facts 重建並存造成的未限定路由重複
  fact；live facts 現為權威來源，避免次要主訴答案污染主要疾病評分。
- 每個入選 disease-vote route 現在各自計算 assessment、frontier、utility、
  must-not-miss 與 completion；只有所有必要路由都完成時才可結束問診。
- 相同 finding 的最新回答會取代舊狀態，避免病人更正／否認後仍被舊 positive 觸發
  Safety；衝突資訊仍保留於 audit。
- 固定順序候選路由不再借用三痛疾病表，避免 seizure、syncope 等主訴產生不相干的
  疾病排名。完整 per-route assessment 另存於 session／decision audit，主要 assessment
  欄位維持相容。

### 前端資料與隱私邊界

- development frontend 的 `backend`／`backendPort` 與兩條部署線的 `fhir`／
  `directFhir` query override 改為預設及 production 全部忽略；只允許明示 development
  flag 加 exact-origin allowlist。
- Backend request 只對同源攜帶 credentials；允許的跨來源開發 endpoint 使用
  `credentials: omit`，避免 cookie 外送。
- FHIR 既往病史排除邏輯不再使用完整 routing keyword catalog；改用窄版 current
  presentation terms 與英文 token boundary，避免 `ENT` 誤命中 Dementia 等診斷。
- doctor 病例畫面使用穩定 route／field labels 顯示候選或歷史問卷資料，不因 runtime
  fail-closed 而退化成 raw key。
