- 發現 49 份 `source_structured_provisional` 問卷雖仍標記待臨床簽核，卻可被 runtime
  自動發現並直接送入病人流程。現在只啟用既有 chest、headache、abdomen 三類；

  整體來源及 route catalog SHA-256、逐路由來源 hash／核准，以及所有 critical／warning
  note 的 resolution 與 rationale。核准產物保留 review notes、RAG sources 與 provenance。
- 撤回 headache／abdomen 三個尚未簽核的新選項。Syncope／出血等 disposition 對應及
  candidate route mapping 仍維持未核准狀態，沒有以工程決定取代臨床政策。
- frontend exporter 預設只處理 development frontend；`--frontend-v2` 才會觸及正式
  部署版，並新增 `--check`、drift detection 與原子寫入。

### AMIE 多主訴問診

- 修正 live `_clinical_facts` 與 legacy semantic facts 重建並存造成的未限定路由重複
  fact；live facts 現為權威來源，避免次要主訴答案污染主要疾病評分。
- 每個入選 disease-vote route 現在各自計算 assessment、frontier、utility、
  must-not-miss 與 completion；只有所有必要路由都完成時才可結束問診。
- 相同 finding 的最新回答會取代舊狀態，避免病人更正／否認後仍被舊 positive 觸發
  Safety；衝突資訊仍保留於 audit。
- 固定順序候選路由不再借用三痛疾病表，避免 seizure、syncope 等主訴產生不相干的
  疾病排名。完整 per-route assessment 另存於 session／decision audit，主要 assessment

## 問診長度觀測與批次化提案評估

延續「如何在不問太多題的前提下取得足夠資訊」的討論，本輪只交付可在現有授權內
收斂的觀測與證據，不修改任何臨床政策或病人流程。

### 交付

- **問診長度觀測值**：`app/services/amie_audit.py` 新增 `interview_length_profile()`，
  每輪記錄各 section 的題數、由病歷預填而略過的題數、漏斗未問到的題數與預填
  覆蓋率。由於 `save_amie_state()` 在 transcript append 之前執行、且 route-guard 與
  safety handoff 路徑根本不呼叫它，兩個 append helper 都會重算，避免落後一輪。
  摘要只含欄位名與計數，測試明確斷言不含答案文字。
- **批次化量測工具**：`scripts/measure_interview_length.py` 以合成、決定性的作答
  比較「提案中的單頁多選」與現行逐題流程。批次分組寫在腳本內而非問卷資料，
  避免「量測一個變更」順帶「做出該變更」。

### 量測結果（合成作答，非真實病人資料）

胸痛未預填時螢幕數 19 → 13。但拆解後，節省的來源多數不是批次化本身：批次只
合併掉 2 個螢幕並讓漏斗多略過 `fixed` 一題，其餘是問診在問到一般病史前就結案。
腹痛只有 `quality` 屬提案分組，頭痛在觸及分組前已完診，兩者皆無變化。

### 因此揭露的兩項既有行為（未修改）

- active 三痛問卷與共用病史有 78 個選項沒有 `semantic_options` 對應。缺口最大的是
  `chest.cardio`（16／16）與 `chest.surgery`（12／12）——心肌梗塞、支架、主動脈
  剝離等病史完全無法進入胸痛鑑別。無 fact 的選項不會影響疾病投票，
  但欄位仍可因 required／priority 政策而被保留；不將兩者混為同一行為。
- `smoke`／`chronic`／`past_meds` 不在任何路由的 `required_fields`，又因上述未接線
  而 `question_utility` 恆為 0，只有在問診剛好還沒結束時才會被問到。同一份胸痛
  問卷，合成作答一律選第一個選項時 18 題完診且三者都問到；一律選最後一個選項
  時 6 題完診且三者皆未詢問。

兩者皆屬臨床政策（§7 高風險，完診條件與問卷內容），因此只記錄於
`backend/docs/funnel_clinical_signoff.md` 第 5、6 節並以 debt-baseline 測試鎖定
既有欄位與選項，未逕行修改。

Code review 後將 debt baseline 從「只鎖總數」改為明確欄位／選項集合，避免新缺口
被其他選項的修正抵銷；批次模擬也改為讓同頁每個答案都經過 AMIE structured
fact 流程，並新增非當前欄位仍會產生 fact 的回歸測試。另外將條件式
自由文字 `chronic_detail` 單獨列為靜態 utility 為 0 的欄位；若它實際被問，仍可經
語意抽取產生 fact，不與三個永適用一般病史欄位混為同一行為。
