# 2026-08-11

## 可停用嘴型的靜態醫師語音模式

- Backend API 由 `0.3.0` 升至 `0.4.0`、development frontend 由 `0.2.6`
  升至 `0.3.0`、deployed Patient frontend 由 `2.0.1` 升至 `2.1.0`、Local
  Avatar service 由 `1.1.1` 升至 `1.2.0`、Integration deployment bundle
  由 `1.4.0` 升至 `1.5.0`；Doctor frontend 不受影響。
- 新增 `AVATAR_ANIMATION_ENABLED`，預設 `true` 保留 MuseTalk。設為 `false`
  時，CosyVoice 仍在本機產生國語／閩南語語音，但 Avatar service 完全略過
  MuseTalk、VAE 與嘴型音訊 encoder 的檢查、下載、warm-up 及推論，以既有醫師
  基準圖和音訊輸出相同 `video/mp4` 契約。
- 靜態與動態模式加入不同 cache key，避免切換後沿用錯誤影片。Health 額外回報
  `animation_enabled`；backend warm-up 只有在動畫啟用時才要求動畫模型 loaded，
  對未回傳新欄位的舊 service 仍維持原本的嚴格判定。
- Backend 會從自己的 `AVATAR_ANIMATION_ENABLED` 取得正常 frontend 流程的有效模式，
  並在每次 warm-up／synthesize request 明確傳給 Avatar service；service 的環境值只
  是直接 caller 或舊 client 未帶欄位時的預設，因此日後切換只需重啟 Backend，無需
  重建 Avatar image 或 container。
- Development 與 deployed Patient 畫面均保留醫師、當次朗讀字幕、聊天文字及
  CosyVoice 音訊。影片提供原生 controls；有聲自動播放遭瀏覽器拒絕時，畫面會
  顯示明確的手動播放入口。D-ID provider、病患 session、問診內容與臨床邏輯未變。
- 本機 `backend/.env` 已選用靜態模式；Avatar service 預設仍為動態，兩個未追蹤
  設定都不含新的憑證，也未提交。
