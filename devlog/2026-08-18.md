## RAG A／B／C 直接分區檢索

- 原本 A／B／C 雖分三次 retrieval，但底層只在同一組 route collections 上追加不同
  query 關鍵字，沒有使用既有的 `clinical_stage` metadata 限制結果；模型 prompt 仍需
  理解「知識庫 A／B／C」的文字角色。
- Backend 新增具名 A／B／C adapter，分別以 Chroma filter 直接綁定
  `diagnosis|workup`、`lab`、`imaging`。固定問卷、醫師 `structured_note` 與舊背景報告
  均只把 Backend 已檢索出的 `retrieved_evidence` 傳給對應模型 request。
- 每筆保存的來源新增 `knowledge_base`、`clinical_stage` 與 `partition_mode`，可追溯
  實際取自哪一分區。Legacy index 無法保證 stage metadata，因此只保留既有
  purpose-query 相容檢索並標示 `legacy_unpartitioned`，不會冒充 v2 分區結果，也不會
  讓預設 legacy 環境因本次更新直接失去報告能力。
- Prompt version 升為 `fixed-questionnaire-direct-abc-rag-v6`，Backend API 升至 `0.7.0`。
  本機 v2 Chroma 以合成胸痛查詢驗證：A 回傳 `diagnosis|workup`、B 回傳 `lab`、C 回傳
  `imaging`。聚焦測試 49 項通過；完整 Backend suite 執行 397 項，其中 395 項通過；
  另 2 項既有 eHIS 靜態契約測試只因本機未掛載 `D:\\ehis\\eHIS` C# 原始碼而 error，
  沒有本次功能 assertion failure。
