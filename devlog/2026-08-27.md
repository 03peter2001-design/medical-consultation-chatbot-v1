# 2026-08-27

## 本機掛號 QR／code 問診 Launcher

- `frontend/launch.html` 成為掛號 QR 的 SMART Provider EHR Launch 入口。既有 FHIR
  Launcher 設定 Box 並選定病人後，OAuth callback 以本次 context 載入 Patient、可選
  Encounter 與 `$everything`，再進入醫師 QR 結果頁；不提供手動 identifier 查詢或病人
  切換。頁面顯示一次性 QR、可複製 raw code、到期倒數及重新核發操作。
- 病患開始畫面新增相機掃描與貼碼入口；成功兌換後必須先恢復 HttpOnly patient session，
  才會以 invitation 綁定的 Patient／Encounter 與預填資料開始既有問診流程。瀏覽器不能
  以 code payload、request prefill 或 FHIR context 覆寫病人身分。
- Backend 新增預設關閉的本機 launcher 發碼端點。它只接受同時具有
  `consultation:read`／`invite:create` 的 loopback local bypass principal，並重用既有高熵
  opaque invitation code、SHA-256 儲存、有效期限、撤銷及原子單次兌換機制；發碼回應標示
  `no-store`，QR 不包含姓名、Patient identifier 或可由前端解碼的 JWT。
- SMART callback 會回報實際 issuer；Backend 只接受與 `FHIR_PUBLIC_ISSUER` 正規化後完全
  相符的值，避免將另一個 FHIR Box 的 Patient ID 錯誤綁定到已核准的資料來源。
- SQLite schema 升至 version 11，將受信任的 FHIR issuer、Patient 與可選 Encounter 從
  invitation 傳遞到 authenticated session，再保存至 consultation。此流程只供 UCC 尚未
  完成前的本機合成資料測試，預設停用；不得使用真實病人資料，正式部署仍需 HTTPS、同源
  proxy、Secure cookie、院方身分與稽核治理。
- Backend API 由 `0.12.0` 升至 `0.13.0`，開發版 frontend 由 `0.12.3` 升至 `0.13.0`；
  獨立控制的 `frontend-v2/` 未修改。
- Backend launcher／invitation／session／repository／授權與 OpenAPI 聚焦測試、Ruff、
  task-owned format check，以及 Node 22 的 frontend 測試、production build 與 OpenAPI
  type check 通過。Browser plugin／Playwright 不可用，改以 headless Chrome/CDP 和合成
  FHIR 回應驗證桌面與手機版的 SMART callback 病人、QR/raw code、倒數、相機 fallback、
  貼碼後的病人綁定與首題；無水平溢出、Vite overlay 或 console error。正式 UCC、院方 OAuth、真實
  FHIR 病例與實體相機仍待整合環境驗證。

## QR 相機的跨瀏覽器 fallback 與部署權限

- 開發版 QR scanner 不再只依賴非 Baseline `BarcodeDetector`；支援時仍優先走原生 API，
  否則 lazy-load 固定且與 Node 18/20 相容的 `@zxing/browser` 0.1.5 與
  `@zxing/library` 0.21.3。最新版因要求 Node 24 而未採用。
- 相機錯誤分為非 HTTPS secure context、權限／站台政策拒絕、找不到相機及裝置占用；
  掃描成功、關閉或元件卸載都會停止 native tracks 與 ZXing controls，貼碼 fallback 保留。
- Integration gateway 的病患 HTTPS Permissions Policy 由 `camera=()` 改為最小範圍的
  `camera=(self)`；geolocation、microphone、CSP 與 iframe 邊界維持原限制，deployment
  validator 防止相機政策退回完全封鎖。
- 開發版 frontend 由 `0.13.0` 升至 `0.13.1`，integration deployment bundle 由 `1.6.0`
  升至 `1.6.1`。Gateway 仍發布 `frontend-v2/apps/patient/dist`；依需求未修改或 promotion
  `frontend-v2/`，所以正式 patient app 的 scanner 移植仍是獨立受控工作。
- Node 22 的 frontend 全套測試、production build、OpenAPI type check 與 Compose config
  通過；以停用 `BarcodeDetector` 的 390×844 headless Chrome、合成 QR 假相機及 mock API
  驗證 ZXing 載入、code 兌換、病患 context／首題、相機釋放與權限拒絕訊息，無 console
  error、overlay 或水平溢出。重建後 gateway healthy，公開 HTTPS response 已回傳
  `Permissions-Policy: camera=(self)`；本機沒有 PowerShell，未直接執行 `.ps1` validator。
