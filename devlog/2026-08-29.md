## Judge relation-matrix coverage v0.7.0

- 最終 prediction／reference matching 改由第三個隔離 judge model adjudicate；judge 使用
  base provider factory 與 `LLM_EXPERIMENT_JUDGE_MODEL` env override，不參與問診、選卷或
  診斷。
- 未使用逐 pair「是否 match」二元問題。每個案例只呼叫一次 judge，要求完整 5×N
  Cartesian matrix，對每對 label 輸出 relation taxonomy 與固定 basis codes；judge 不得
  回傳 coverage、重新排序或自由文字 rationale。
- 本機驗證 contract version、狀態、完整 pair 數、索引、重複、relation／basis 一致性，
  再以 deterministic maximum bipartite matching 實作一對一計分。只有 equivalent 與
  reference explicit containment 能形成確定命中邊。
- Pair-level `indeterminate` 會產生 lower／upper coverage；上下界不同時單一
  `coverage_at_5` 設為 null。全體 abstention 也不會被誤報為 0/N；provider 或 schema
  failure 不會退回 lexical matching。
- 結果保存完整 adjudication、definite／possible matched pairs、provider、judge model、
  contract／scoring method 與 ordered input SHA-256，可從保存結果離線重算 coverage。
- Reference diagnoses 的資料邊界由 local-only evaluator 改為送往 `.env` 指定的外部 judge
  provider；仍不會進 doctor／patient prompt。此研究模式只允許已明示授權的 synthetic／
  educational scenario。
- 新增 judge env、單次呼叫、prompt isolation、惡意 label、完整 matrix、taxonomy、
  deterministic one-to-one matching、indeterminate bounds 與 fail-closed 回歸測試；離線
  測試共 75 項通過。
- 首次 Gemini smoke 的 rich provider-side enum schema 在 judge 階段穩定回傳 HTTP 400；
  依 Gemini structured-output 支援子集將 provider schema 縮為基本型別，relation、basis、
  contract、索引與完整矩陣仍全部由本機嚴格驗證，未放寬 scoring contract。泛化 A–E/R1
  judge-only smoke 隨後成功。
- 完整 Sample 1 smoke 成功產生 15 個 pair assessments。Judge 將 `Bronchiectasis` 與帶可能
  病因限定詞的 reference 分為 `reference_explicitly_contains_prediction`，最終 coverage
  為 1/3；`Bronchogenic carcinoma` 對 `Primary lung cancer` 被分為 narrower，依保守政策
  不計分。結果記錄實際 judge model `gemini-3.6-flash` 與 input SHA-256。

## CC-first 自動選卷 v0.6.0

- CLI 問診改為固定先詢問 `chief.json` 的 `reason`；病人公開回答主訴後，醫師 agent 才能
  選擇後續疾病問卷。省略 `--questionnaire` 為自動選卷，明確路徑則保留為相容覆寫，但
  兩種模式都會先問 CC。
- Selector 僅收到 CC 公開回答與已治理的 route metadata，不會收到 referral、其他
  patient facts／concerns、reference diagnoses 或 evaluator 資料；選定後才開始
  `basic + history + disease` 問卷。
- 候選使用既有 `backend/domain/questionnaire_routes.json` 的權威 label、keywords、
  disposition 與 clinical domain。預設只暴露 3 份 runtime-approved questionnaire；明示
  provisional 後暴露 36 份 questionnaire disposition，10 份 handoff 與 6 份 urgent route
  不會進入 selector。
- Selector 可用 `questionnaire_id=null` abstain；未知 id 重試一次後失敗關閉，CC 無法回答
  時不選卷，且不使用第一份候選作 fallback。
- 結果記錄 `chief_complaint_turn_id` 與 `questionnaire_routing_strategy`；`max_turns` 將 CC
  算作第一輪。新增 catalog governance、資訊隔離、abstention、未知 route、explicit
  override 與 CLI auto-routing 回歸測試。
- 離線驗證共 64 項測試，Ruff lint／format 均通過。真實 Gemini 以 Sample 1 執行一輪
  CC-first smoke：第一題取得咳血主訴後，自動選到 provisional `respiratory_issues`，並在
  問卷輪數截斷下照常輸出五個暫定疾病與 coverage；未將 reference 送入 selector。

## Top-5 疾病與 reference coverage v0.5.0

- 醫師診斷契約新增 `ranked_diagnoses`，無論是否能提出 primary diagnosis，都必須回傳
  依可能性排序的五個 unique 疾病；既有 differential result 以相同五項保留相容性。
- Scenario pack 的 reference 數量為 1–6 個，不固定為五個；coverage@5 定義為 top-5
  命中的 unique reference 數除以完整 reference 數，因此 ABCDE 對 BCDEF 為 4/5，六個
  reference 的理論最高值為 5/6。
- Reference diagnoses 仍不會送入 doctor／patient prompt，只在診斷結束後交給本機
  evaluator。結果保留 prediction、reference、matched labels、分子、分母、fraction、
  coverage 浮點值及 matching method。
- 首版採 `unicode_normalized_exact_v1`：只正規化 Unicode、case、標點與空白，不使用
  substring、模型裁判或未審核同義詞，故指標明確屬 lexical coverage，不冒充臨床概念
  coverage。
- 新增 evaluator、top-5 數量／唯一性、4/5、5/6 與 lexical-not-fuzzy 回歸測試；離線
  測試增至 56 項。
- 真實 Gemini 一輪 smoke 成功輸出五個疾病與 evaluation。Sample 1 因 prediction 使用
  `Bronchiectasis`／`Lung cancer`，reference 使用帶限定詞的較長 label，保守 exact
  matcher 結果為 0/3；此結果確認 metric 不會暗中做未定義的 semantic matching，也顯示
  未來建立 reviewed canonical alias 表的必要性。

## 病人契約錯誤全面安全降級 v0.4.2

- 完整 Gemini 問診再次遇到模型同時回傳 `cannot_answer=true` 與 fact 引用；這類矛盾
  payload 現會直接捨棄並轉為 deterministic unknown，不再中止問診。
- 其他 PatientAgent 本機契約錯誤仍先重試一次；第二次失敗後安全降級為 unknown，並在
  transcript 記錄 `fallback_reason=model_contract_validation_failed`，未驗證內容不會進入
  公開逐字稿。
- 正常 cannot-answer、無 grounding 回答、矛盾 cannot-answer 與重試耗盡均有不同
  fallback audit reason。未知 fact 或非法 canonical option 不會被接受為有效答案。
- 條件題缺少 canonical 前置答案時，orchestrator 改以 `conditions_unresolved` 和不完整
  資料 limitation 結束，仍允許醫師明確 abstain，而不是拋出流程例外。
- 新增／更新回歸測試後共 50 項通過。
- 以使用者相同完整命令實跑 `Sample 1 + chest` 成功：21 輪問答、略過 1 個不適用條件
  題、`questionnaire_complete=true`，最後產生 provisional diagnosis；未再發生契約錯誤。
