## Transient Doctor UCC 401 hardening

- Traced the initial pair of `/v1/doctor/consultations` 401 responses to the
  immediate frontend refresh retry plus zero-leeway JWT `iat` validation. The eHIS
  issuer already backdates `nbf`, but a few seconds of host clock drift can still
  make a newly issued `iat` appear to be in the future until the next user action.
- Backend v0.8.2 now permits a bounded 30-second JWT clock skew (configurable only
  from 0–300 seconds), propagates the authenticated principal across sync route
  execution, and marks all API responses `no-store`. Authentication signatures,
  scopes, tenant isolation, patient data, and clinical behavior are unchanged.
- Doctor frontend v2.1.1 bypasses browser caching for both an initial API request
  and its refreshed-token retry. Integration bundle v1.5.3 applies no-cache at the
  Nginx/IIS boundaries and derives the eHIS iframe cache-buster from the Vite entry
  hash so an ordinary refresh does not retain an obsolete bundle.
- Focused JWT/context and cache-header tests, all Frontend v2 tests, and deployment
  static validation passed during development. Production deployment and an
  authenticated eHIS browser acceptance check remain separate operational steps.
