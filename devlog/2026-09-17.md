# 2026-09-17

## A100 vLLM manifest v0.4.1

- Added a ready-to-copy A100 80GB model manifest for the existing sequential vLLM
  evaluation flow.
- Removed the RTX Pro-only Nemotron Triton workaround and enabled all 11 supplied
  checkpoints. Memory-tight models use a 4096-token limit, eager execution, and a
  single sequence. The Blackwell-oriented NVFP4 checkpoint is treated as an explicit
  compatibility probe whose expected A100 startup failure remains separate from
  accuracy results.
- Kept every other checkpoint path and visual/text capability assignment aligned
  with the original 11-model manifest.

## RTX Pro 6000 vLLM model matrix v0.4.0

- Added a dependency-free OpenAI-compatible vLLM client supporting text and base64
  image messages, JSON-schema scoring, endpoint/model/version provenance, bounded
  retries, and the same failure-inclusive denominator as prior runs.
- Added a single-endpoint runner and sequential matrix orchestrator. The orchestrator
  inspects local checkpoint configuration, binds vLLM to loopback, performs health and
  one-case smoke checks, writes immutable per-model outputs and server logs, stops only
  its own process group, records startup/inference failures, and continues by default.
- Matrix provenance automatically captures GPU/driver, Python/platform, vLLM CLI/API
  versions, inspected checkpoint metadata, and exact model launch commands.
- Added an example manifest for all 11 checkpoint paths supplied on the RTX Pro host.
  Explicit text-only models run `context_only`; vision-capable models run all four
  visual arms; `gemma-4-31b` uses target-host configuration inspection because its
  directory name does not establish multimodal capability.
- Added model-specific launch guidance from current official documentation, including
  Nemotron Omni's RTX Pro/vLLM 0.20.0 settings and Qwen2.5-VL AWQ half precision.
  Quantization is otherwise left to checkpoint configuration rather than inferred
  from filenames.
- Added a matrix analyzer that reports context accuracy for all completed models and
  matched-image accuracy, true-image gain, and matched-over-wrong grounding only for
  models that actually ran all image modes.
- Added deterministic tests for vLLM request payloads, data-URL image encoding,
  structured output, local vision detection, manifest validation, and launch command
  construction. No target checkpoint was downloaded or started on this development
  host; target-GPU execution remains required.

## Generalist medical VLM visual comparison v0.3.0

- Added an isolated Gemini Developer API benchmark adapter under
  `AgentClinic/medgemma_eval/`. It reads the backend's existing Gemini key and model
  selection without modifying backend runtime behavior or recording the credential.
- Reused the exact MedGemma four-arm cohort, prompt version, seed, option order,
  image checksums, mismatched-image selection, and exact A–E scoring. Added strict
  case-level comparison that rejects prompt, option, or image mismatches.
- Completed 480/480 scorable `gemini-3.6-flash` responses using `google-genai` 2.16.0.
  Accuracy was 88.3% for proxy context only, 96.7% for context plus the matched image,
  90.0% for context plus a mismatched image, and 90.0% for task/choices plus image.
- Against local `medgemma:27b`, Gemini improved matched-image accuracy by 34.2 points
  (41 helpful and 0 harmful paired flips, p<0.001). On the 90 direct-diagnosis cases,
  Gemini measured 97.8% versus MedGemma's 66.7% (+31.1 points, 28/0 flips, p<0.001).
- Gemini also showed positive within-model grounding: +8.3 points for matched image
  versus no image (p=0.013) and +6.7 points versus a mismatched image (p=0.039).
- The tracked report treats Gemini's 90.0% task/choices-plus-image accuracy as a major
  contamination or memorization warning. Public NEJM results are not clinical
  validation and do not authorize sending patient images to an external API.
- Added deterministic configuration, credential-redaction, and paired-comparison
  tests. No new dependency was installed; the benchmark uses the backend's existing
  environment. Raw images and generated JSONL/CSV reports remain ignored.
