# 2026-09-23

## MedKGI opt-in 研究引擎（Backend v0.15.0）

- 新增需明確設定 `INTERVIEW_ENGINE=medkgi` 才會啟用的 gated 研究路徑；既有
  `questionnaire` 維持預設，API 與既有病例資料保持相容。
- 診斷核心依 repository 內 MedKGI 論文的方法，改由本機 PrimeKG 衍生圖譜、
  Bayesian posterior、資訊增益選題及停止條件負責。LLM 不再自由決定疾病排名，
  僅能以固定 schema 做 evidence-grounded 的自由文字實體／fact 擷取；選中的題目
  使用經審查的固定問卷文字，不由 LLM 生成或改寫。
- Safety 規則維持獨立且先於圖譜推論。缺少／損壞資產、manifest 或 checksum 不符、
  實體無法可靠對齊及推論失敗都必須 fail closed，不可靜默退回 RAG 或 LLM 猜測。
- RAG 可繼續支援非診斷性的理學檢查、檢驗、影像工作草稿與醫師文獻問答，但不得
  影響 MedKGI posterior、下一題、停止條件或 Safety。

## 資產與 provenance

- 新增 PrimeKG CSV 的離線建置流程，預設輸出
  `backend/data/medkgi/{primekg.json,manifest.json}`；manifest 保存來源版本、
  checksum 與建置設定。既有輸出預設不覆寫，輸入或模型失敗時不發布半成品。
- PubMedBERT embeddings 為 opt-in 後備資產，預設輸出
  `backend/data/medkgi/pubmedbert_embeddings.npz`。精確與編輯距離對齊優先；
  embeddings 只比對標準英文實體，不直接判讀中文／台語病人原話。
- 未傳 `--embedding-model` 時，建置器不載入模型或存取網路；本機模型目錄採
  local-only，只有 builder 明示 `hf://` 才允許 Hugging Face resolution。Runtime
  的 `MEDKGI_PUBMEDBERT_MODEL` 只接受既有本機模型目錄，不接受 repo ID，也不會
  下載模型。PrimeKG 原始資料、模型快取與所有衍生資產均留在被忽略的本機資料目錄，
  不提交 repository。
- 官方 PrimeKG file `6180620` 已成功建置及載入；輸出含 26,474 nodes、151,338
  disease-symptom edges、64,388 disease-disease edges，並在建置時移除 151,682 筆
  duplicate rows。
- 技術上可載入不代表路由可用。目前每條 active route 都有 governed profiles 缺少
  phenotype edges 或發生語意碰撞，strict startup prevalidation 因此將 MedKGI
  標記為 unavailable，明示選用時回傳 503 fail closed。

## 臨床、隱私與相容性

- 本次是研究實作，不是醫療器材、臨床核准、確診或治療建議。MedKGI posterior 是
  內部排序值，不是校準患病機率；所有結果保持未經醫師確認並須由合格人員審閱。
- 既有 LLM 若指向外部服務，受限自由文字擷取仍可能傳送病人文字；正式使用真實資料
  前，仍須完成告知同意、供應商契約、資料保存地區、訓練政策、資安與稽核審查。
- 預設 `questionnaire`、舊 `amie` 回退選項、SQLite schema、FHIR／SMART contract
  及 frontend 行為不因本次功能自動改變；MedKGI 資產存在也不會自動切換引擎。
- PrimeKG 授權、版本固定、圖譜／詞彙臨床審查、離線黃金集、校準、subgroup 與失敗
  模式評估尚未構成正式臨床核准，必須在任何真實病人 rollout 前另行完成。
- PubMedBERT fallback 的相似度不是臨床概念等價證據，不得用來核准或掩蓋 mapping
  collision 與 coverage 缺口。MedKGI 啟用前仍需 clinician-reviewed terminology
  mapping、各 route coverage reconciliation 與 strict prevalidation。
